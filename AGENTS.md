## Hosting
- No longer connected to Lovable. Deployed as a standalone Node.js server (Hostinger): `npm run build` → `npm start` (`node .output/server/index.mjs`), nitro preset `node-server` in `vite.config.ts`.
- `VITE_*` env vars are inlined at build time; everything else is read at runtime. Template: `.env.example`.
- Three installable apps from one site (see `docs/APPS.md`): `appArea(pathname)` in `src/lib/web-manifest.ts` maps `/painel` → Loja, `/entregador` → Entregador, the rest → Cliente; the root `head` links that app's manifest/icon/title, and `SiteHeader`/`BottomNav`/`CartBar` show only that area's links. Panel and courier sections are `?aba=` search params. Play Store TWA verification is `/.well-known/assetlinks.json` from `ANDROID_SHA256_FINGERPRINTS`.
- Google login uses `supabase.auth.signInWithOAuth` (provider must be enabled in Supabase Auth); push uses FCM HTTP v1 directly with `FIREBASE_SERVICE_ACCOUNT` (`src/lib/push.server.ts`).

## Marketplace rules
- Order totals, delivery fee and Asaas split are computed only in `createOrder` server fn (orders have no client INSERT grant) — prevents price tampering.
- Fee/distance/open-hours helpers live in `src/lib/market.ts`, shared by client and server so UI estimates match charged values.
- Asaas payment status updates arrive via `/api/public/asaas-webhook` (verified with `asaas-access-token` header) plus a manual refresh fn as fallback.
- Product/cover images are URL fields because public storage buckets are blocked in this workspace.
- Delivery-only: delivery fee rule (own couriers = free up to FREE_KM_OWN, then per-km) lives in `deliveryFee` in `src/lib/market.ts`; promo price via `effectivePrice` applied in `createOrder`.
- Delivery completion only via `confirm_delivery(order, pin)` RPC; DB triggers (`orders_guard`, `stores_guard`, `couriers_guard`) block clients from editing totals, PIN, ratings and courier approval.
- Admin = row in `user_roles` (role 'admin'), checked with `has_role`; header roles come from `useRoles` in `src/lib/roles.ts`.
- Phone product photos are compressed client-side (`src/lib/image.ts`) and stored as data URLs in `products.image_url` — public buckets are blocked.
- Courier documents live in private bucket `courier-docs/<user_id>/…`; admins view via signed URL from `courierDocUrl` — never public links.
- Platform couriers (stores with `own_couriers = false`): `splitOrder` in `src/lib/market.ts` gives the whole delivery fee to `orders.courier_payout` and charges commission on products only. Couriers see paid unassigned orders via the `open_deliveries` RPC (nearest store first, no customer data) and take one with `accept_delivery` (atomic). Admin pays them from the "Repasse entregadores" tab (`sendCourierPayout`, claims `courier_payout_id`).
- `orders_guard`/`stores_guard` must stay SECURITY INVOKER: inside SECURITY DEFINER `current_user` is the owner, so the `current_user = 'authenticated'` check never fires (that bug let clients edit totals/payouts until migration 0013).
- Column privacy (migration 0014): `orders.delivery_pin` and `stores.pix_key/pix_key_type/asaas_wallet_id` are not granted to `anon`/`authenticated`; the browser lists columns from `src/lib/columns.ts` (never `select("*")` on orders/stores), the customer gets PINs via `my_order_pins()` and the owner reads Pix via `my_store_pix()`. A new column on these tables must be added to the GRANT lists and to `columns.ts`. Realtime publishes only id/status-type columns of these tables.
- Test accounts (migration 0015): users listed in `public.test_accounts` (no client grants; e.g. the Play Store reviewer login) are isolated in `open_deliveries`/`accept_delivery` — a test courier only gets orders of test-owned stores, real couriers never do. Add/remove testers there via SQL. Admins can open and order from these hidden test stores (policy "admins read test stores" via `is_test_user`, migrations 0017/0018; same check in `createOrder`), and test stores are open 24 h. Never reference `test_accounts` directly in an RLS policy: clients can't read it, so the whole table query fails with 403.
- Courier ↔ store affiliation (migration 0016): the courier app makes a one-time 6-digit code (`link_code_create`, 10 min), the owner types it (`link_code_lookup` → `link_code_redeem`, 1 h–8 weeks, 5 wrong codes per 15 min) in "Meus entregadores"; `store_courier_links` holds the period, with no client grants (RPCs `store_links`/`courier_links`/`link_end`). A courier has one active store at a time. `orders_guard` lets a store put on an order only an affiliated courier (`is_affiliated`), and `list_couriers` shows stores only their affiliates. Paying affiliated couriers is agreed outside the app; helpers in `src/lib/affiliation.ts`.
- Customer cancellation: `cancelMyOrder` (`src/lib/orders.functions.ts`) only while status is in `CUSTOMER_CANCELLABLE` (before preparing, per /termos); it claims the order as `cancelado` first, then `voidPayment` refunds the Asaas charge if paid or deletes it if open (whole installment plan for cards), and reverts the status if Asaas fails. Store-side cancel works the same way through `storeCancelOrder` (owner only, `STORE_CANCELLABLE` = pago/preparando, push to the customer); since migration 0019 `orders_guard` no longer lets clients set `cancelado`, so every cancel goes through a server fn that refunds.
- Address search: `AddressInput` shows TomTom suggestions (`suggestAddress` in `src/lib/places.functions.ts`, server-side `TOMTOM_API_KEY`, auth required); `findAddress`/`addressFromGps` (`src/lib/address.ts`) try TomTom then fall back to the OpenStreetMap chain in `market.ts` (Sete Lagoas only, so used only when searching around there). Searches are not tied to one city: checkout searches around the order's store (`storeArea`), Minha conta around the customer's saved point, the store panel all of Brazil. TomTom terms (11.4) forbid storing its results, so the saved position is the pin the customer confirms on `PinMap` (Leaflet + OSM tiles). `locateMe` lets the GPS settle up to 8 s and keeps the most precise reading.
- Order tracking page (`pedido.$id.tsx`): horizontal `Progress`, delivery window from `deliveryWindow` in `market.ts` (order time + prep/rain + pickup + ride; live minutes from courier GPS fresher than 5 min), `OrderMap` (Leaflet: store, delivery point, courier). Before preparing the customer can fix the address with `updateOrderAddress` (service role, only moves within `ADDRESS_EDIT_MAX_KM` so the paid fee holds).
- Manual Pix payouts: `src/lib/payouts.functions.ts` groups delivered orders with `payout_id IS NULL`, marks them before calling Asaas `/transfers`, and rolls back on failure.
